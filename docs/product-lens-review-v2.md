## 1. 축소안의 진짜 힘 — "부정 선호"

이 아이디어의 핵심은 위시리스트가 아니라 **NO리스트**입니다. 둘은 기능이 비슷해 보이지만 **심리적 마찰이 근본적으로 다릅니다.**

| | 위시리스트 | NO리스트 |
|---|---|---|
| 화행(speech act) | **요구** — "이거 사줘" | **정보 제공** — "이건 이미 있어" |
| 작성자 감정 | 민망함, 염치없음 | 배려, 도움 |
| 안 썼을 때 결과 | 아쉬움 | **중복 선물 = 실패한 선물** |

> **한 문장 정의**
> **"갖고 싶은 걸 말하는 대신, 필요 없는 걸 말하게 하는 선물 서비스."**

이게 이 제품의 포지셔닝 문장이 되어야 합니다. 위시리스트는 유지하되 **부차적 기능**으로 두고, 온보딩의 첫 화면은 NO리스트여야 합니다.

**NO리스트 입력 항목 제안** (심리적 마찰이 낮은 순)

1. **이미 있는 것** — 카테고리 단위 ("텀블러 3개 있음")
2. **못 쓰는 것** — 알러지, 사이즈, 피부타입, 반려동물
3. **취향 아닌 것** — 향, 색, 브랜드
4. **부담스러운 것** — 금액대 상한 (⚠️ 이것도 말하기 민망한 항목)

## 2. 🔴 발견된 모순 — 펀딩 vs 민망함

축을 좁히면서 **전제와 기능이 충돌**하게 됐습니다.

```
전제:  "원하는 걸 명확하게 요구하기 민망한 사람"
펀딩:  "나 100만원짜리 컴퓨터 갖고 싶어. 다들 돈 모아줘."
                    ↑
            민망함의 최고봉
```

NO리스트조차 민망해서 위시리스트를 못 쓰는 사람이, **고가 선물 펀딩을 스스로 개설한다는 건 앞뒤가 안 맞습니다.**

### 해결책: 개설 주체를 뒤집으세요

| | 기존 설계 | 제안 |
|---|---|---|
| 펀딩 개설 | **받는 사람**이 "100만원 컴퓨터 갖고 싶다" 등록 | **주는 사람(주최자)** 이 위시리스트를 보고 "이거 같이 사주자" 제안 |
| 받는 사람의 행위 | 요청 | *(없음)* 위시리스트에 올려둔 것뿐 |
| 민망함 | 최상 | **제거됨** |

받는 사람은 그냥 갖고 싶은 걸 **가격표 없이** 올려둡니다. 주는 사람들이 보다가 "혼자는 무리인데 같이 하면 되겠다" → 주최자가 펀딩 개설.

이미 답변하신 **"최종 구매 버튼은 주최자가"** 와도 일관됩니다. 개설도 주최자가 하는 게 자연스럽습니다.

> **부수 효과**: "이 선물은 혼자 사기엔 부담스럽다"는 판단을 **시스템이 대신** 해줍니다. 평소 주고받던 금액대(v1의 장부 데이터)를 여기서 재활용할 수 있습니다.

## 3. 선물 트레이드 — 질문에 대한 답

> "구매자가 선물한다고 바로 주문 확정되는 게 아니라 단순히 주문 형식으로 넣는 거라, 받는 사람이 취소하면 결국 주문취소가 되는 거 아니야?"

### ✅ 맞는 부분

**정확합니다.** 지연 확정(deferred confirmation) 모델은 실제로 존재합니다. 카카오 선물하기 배송상품이 이렇게 동작합니다:

```
A 결제 → B에게 알림 → B가 배송지 입력 → 그때 발송
                    └→ B가 거절 / 기한 초과 → A에게 환불
```

받는 사람이 확정권을 갖는 구조 자체는 **문제없고, 이미 검증된 패턴**입니다.

### ⚠️ 갈리는 부분 — 문제는 "상품 변경"이 아니라 **"차액"** 입니다

| 시나리오 | 판정 |
|---|---|
| B가 거절 → A에게 전액 환불 | ✅ **깨끗함.** 이미 업계 표준 |
| B가 **같은 금액**의 다른 상품 선택, 차액 없음 | 🟡 가능. 단 A의 결제금이 특정 상품에 묶이지 않는 구조 필요 → **자체 커머스이거나 제휴 필수** |
| B가 싼 상품 선택 + **차액을 포인트로 수령** | 🔴 **여기가 막힙니다** (아래) |
| B가 싼 상품 선택 + 차액을 A에게 환불 | 🟡 법적으론 깔끔. 그러나 **A가 알게 되어 컨셉이 붕괴** |

**🔴 차액 포인트의 문제**

B에게 남는 5,000p는 "특정 상품의 대금"이 아니라 **다음에 아무거나 살 수 있는 가치**입니다. 이 성격은 **선불전자지급수단**에 해당할 소지가 큽니다. 발행하려면 금융당국 등록 요건이 따르고, 미상환 잔액에 대한 관리 의무도 생깁니다.

> ⚠️ 정확한 적용 여부는 **법률 검토가 필요한 사항**입니다. 다만 학생 팀이 실서비스로 넘길 때 확실히 걸리는 지점이고, 수업 프로젝트 범위에서도 "이걸 어떻게 처리할 건가"는 질문받기 좋은 포인트입니다.

### ✅ 대안 A — 차액 무환급, 동일 예산 내 교환

```
A가 3만원 결제 → B는 "3만원 예산" 안에서 재선택
                 → 2.5만원 상품을 골라도 차액 환급 없음
```

- 포인트 발행 **없음** → 규제 회피
- B에게는 3만원에 가깝게 고를 유인이 생김
- 구현 단순

**단점**: B가 손해 보는 느낌. 그리고 A는 여전히 "내가 고른 마우스"가 배송된 줄 앎 → 나중에 "그 마우스 잘 써?" 문제 잔존.

### ✅✅ 대안 B — 애초에 예산만 주기 (**권장**)

교환은 **잘못된 선택을 사후에 고치는** 기능입니다. 애초에 잘못 고르지 않게 하는 게 낫습니다.

```
A: "3만원어치 선물할게"  →  B: NO리스트/위시리스트 안에서 직접 선택
```

이 구조는 세 문제를 **동시에** 없앱니다:

| 문제 | 해소 방식 |
|---|---|
| 차액 포인트 규제 | 애초에 차액이 없음 |
| A에게 숨기기 | 처음부터 A가 알고 있음 — **숨길 게 없음** |
| 교환·반품 물류 | 주문이 한 번만 발생 |

그리고 무엇보다 **제품의 전제와 완벽히 일치합니다.** "말하기 민망하다"는 문제를 *은폐*가 아니라 *구조*로 푸는 것.

**대안 B의 비용**: A가 **"골라준 마음"** 을 잃습니다. 선물의 절반은 고르는 정성인데, 예산만 주면 상품권과 다를 게 없어집니다.

### 🎯 절충안 — "A가 후보 3개, B가 선택"

```
A: B의 NO리스트로 필터링된 목록에서 후보 3개 선택
B: 그중 하나 확정 (또는 "다시 골라줘" 1회 요청)
```

- A는 고르는 재미와 정성을 유지
- B는 최종 선택권 보유 → 실패 확률 급감
- **A는 B가 3개 중 뭘 골랐는지 알아도 전혀 어색하지 않음** — 그게 설계니까
- 차액 없음, 포인트 없음, 교환 없음

> **권장: 절충안을 MVP로.** "선물 교환"이라는 사후 기능을 통째로 삭제하고, 그 니즈를 사전 설계로 흡수합니다.

| 마감기한 | O | ✅ | — |

### 🔴 지분 표시의 충돌

이 앱의 테마는 **"민망함 제거"** 입니다. 그런데 참여 금액을 공개하면:

- 5만원 낸 사람 옆에 1만원 낸 사람 → **새로운 민망함 생성**
- 받는 사람도 "누가 얼마 냈는지" 알면 관계가 계산으로 환원

**옵션**

| 안 | 내용 | 일관성 |
|---|---|---|
| a | 전원 공개 (현재 답변) | ❌ 테마와 충돌 |
| b | **참여자 명단만 공개, 금액 비공개** | ✅ 권장 |

## 5. 가장 큰 실행 리스크 — 콜드스타트

축을 좁혀도 이 문제는 남습니다. **B가 NO리스트를 쓰고, A가 그걸 봐야** 합니다. 양쪽 다 가입해야 하면 시연할 때 빈 화면을 봅니다.

### 완화책: **앱 설치 없이 링크로 열람**

```
B(받는 사람): 앱에서 NO리스트 작성 → 공유 링크 생성
                    ↓ 카카오톡으로 전달
A(주는 사람): 링크 클릭 → 웹에서 바로 열람. 가입 불필요
                    ↓
              선물하고 싶으면 그때 가입
```

- 진입 장벽이 **한쪽에만** 존재
- 링크가 카톡으로 퍼지는 것 자체가 바이럴 채널
- 팀 프로젝트 시연에서도 강력함 (QR 찍고 바로 열람)

> 이 링크 공유 모델을 **v1 필수 기능**으로 잡으시길 권합니다.

## 6. 권장 MVP v2

> **"갖고 싶은 걸 말하는 대신, 필요 없는 걸 말하게 하는 선물 서비스"**

### v1 (필수)

- ✅ **NO리스트 작성** — 이미 있는 것 / 못 쓰는 것 / 취향 아닌 것
- ✅ **가입 없이 열람 가능한 공유 링크** — 콜드스타트 방어
- ✅ **위시리스트** (가격 비공개 옵션) — 부차적 위치
- ✅ **후보 3개 → 받는 사람 확정** 플로우 (교환 기능 대체)

### v2 (다음)

- 🔸 **주최자 개설형 공동 펀딩** — §4 결정 사항 확정 후
- 🔸 중복 선물 경고 (과거 수신 이력 기반)
- 🔸 감사 메시지 자동 취합

### 삭제

- ⛔ **선물 교환 + 포인트 환급** → 절충안(§3)이 니즈를 흡수하므로 **불필요**
- ⛔ 최저가 추천 / 크롤링
- ⛔ 경조사 장부 (v1 문서의 축 — 이번 범위 밖)

### Anti-goal

자체 커머스 · 포인트 발행 · 소셜 피드 · 가격 비교
