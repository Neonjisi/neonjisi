## 1. 진단 — 이 제품의 심장은 "상호성(reciprocity) 데이터"

네 기능 중 **해자(moat)가 있는 것은 하나뿐**입니다.

> **"저 사람이 내 결혼식에 얼마 냈지?"**
> 한국에서 수십 년째 종이 장부와 엑셀로 관리되는, **빈도가 높고 실패 비용이 큰** 문제입니다.
> 그리고 **데이터가 쌓일수록 이탈 비용이 커지는** 유일한 기능입니다.

나머지 3개(최저가·펀딩·교환)는 복제가 쉽거나, 이미 카카오 선물하기가 하고 있거나, 법적 진입장벽에 막힙니다. (§3 참조)

**핵심 통찰**: 이 서비스는 "선물 앱"이 아니라 **"관계 원장(ledger)"** 으로 포지셔닝할 때 가장 강합니다.

## 2. 추가 기능 제안

### A. 기록 자동화 — 부가기능이 아니라 **제품의 생사**

장부 앱이 죽는 이유는 기능 부족이 아니라 **수기 입력의 귀찮음**입니다. 여기서 지면 나머지 기능은 의미가 없습니다.

| 기능 | 설명 | 왜 중요한가 |
|---|---|---|
| **계좌이체 SMS/알림 파싱** | "홍길동 100,000원 입금" 알림을 읽어 장부 후보로 자동 등록 | 입력 마찰 → 0. Android 알림 접근 권한으로 구현 가능 |
| **모바일 청첩장·부고 링크 파싱** | URL 붙여넣기 → 이름·날짜·장소·관계 자동 채움 | 경조사 대부분이 카톡 링크로 전달됨 |
| **봉투/방명록 OCR 일괄 등록** | 결혼식 후 봉투 더미를 사진으로 → 이름+금액 일괄 추출 | **본인 결혼식이 최대 데이터 유입 순간.** 한 번에 200명 유입 |
| **카카오 선물하기 내역 연동/파싱** | 주고받은 선물 자동 기록 | 선물 쪽 데이터 소스 확보 |

### B. 관계 인텔리전스 — 장부를 "조언"으로 바꾸는 층

| 기능 | 설명 |
|---|---|
| **상호성 밸런스** | 관계별 `받은 총액 − 준 총액`, 미정산 관계 목록 |
| **금액 추천 + 물가 보정** | "2019년에 5만원 받으셨습니다 → 2026년 기준 7만원 권장". 관계 유형(직장/친척/친구) × 참석 여부 × 지역 반영 |
| **가구 단위 공동 장부** | 부부가 하나의 장부 공유. **경조사는 개인이 아니라 가구 단위로 오갑니다** — 없으면 데이터가 반쪽 |
| **모임 단위 갹출 장부** | 동호회·회사 팀 단위 공동 경조사금 관리 + 정산 |
| **라이프이벤트 예측 알림** | "김OO님 결혼 D-30, 예상 축의금 7만원, 지난 상호작용 3건" |

### C. 취향 / 중복 방지 — 초안의 "지난번과 다른 선물" 니즈 직결

| 기능 | 설명 |
|---|---|
| **NO 리스트 / 보유 목록** | 위시리스트보다 **"이미 있는 것 / 싫어하는 것"이 훨씬 강력합니다.** 알러지, 사이즈, 기피 브랜드 |
| **중복 선물 경고** | "작년에 같은 카테고리(향수)를 선물하셨습니다" |
| **익명 취향 힌트** | 받는 사람이 대놓고 말하기 민망한 항목을 친구가 대신 등록 |
| **선물 후기(비공개)** | 준 사람에게는 보이지 않는 만족도 기록 → 추천 학습 연료 |

### D. 펀딩 운영 규칙 — **설계하지 않으면 굴러가지 않습니다**

초안 3번은 해피패스만 있고 **실패 경로가 비어 있습니다.** 아래는 선택이 아니라 필수 결정 사항입니다.

- [ ] **미달 시 처리**: 환불 / 하향 대체품 / 차액 본인 부담 — 셋 중 무엇?
- [ ] **초과 시 처리**: 비례 환불 / 포인트 전환 / 상위 옵션 업그레이드
- [ ] **마감 기한 & 최소 인원** 정책
- [ ] **참여자 지분 표시 + 감사 메시지 자동 취합** (100만원을 4명이 냈으면 감사도 4명에게)
- [ ] **주최자(간사) 역할** — 최종 구매 버튼은 누가 누르는가

### E. 리텐션 훅

| 기능 | 설명 |
|---|---|
| **"잘 쓰고 있어요" 사진 리포트** | 받은 사람이 3개월 뒤 사용 사진 1장 → 준 사람에게 푸시. 감정적 보상 = 재방문 |
| **답례 리마인더** | "받은 지 3일, 감사 인사 보내셨나요?" |
| **연말 리포트** | "올해 경조사비 340만원, 받은 건 210만원" — 카카오/토스식 연말결산 = 바이럴 |

## 3. 빼야 할 것

### 🔴 4번 선물 교환 — MVP에서 제외 권장

시나리오는 매력적이지만 구조적으로 막힙니다.

1. **교환/환불은 판매자와의 계약**입니다. 커머스 사업자가 아니면 중간에 낄 수 없습니다. 카카오 선물하기가 이걸 할 수 있는 이유는 **본인이 판매 중개자**이기 때문입니다.
2. **5,000p 포인트는 선불전자지급수단**입니다. 실서비스라면 전자금융거래법상 등록 대상입니다.
3. "준 사람은 모르도록"을 보장하려면 **배송·정산 흐름 전체를 소유**해야 합니다.

> **판단**: 이 기능 하나가 팀 리소스를 전부 잡아먹습니다. 수업 프로젝트라면 컨셉 시연까지는 가능하나, MVP 범위에는 넣지 마십시오.

### 🟡 2번 최저가 추천 — 범위 축소 권장

fallcent 같은 가격 이력 서비스는 **그 자체가 별도의 제품**입니다. 크롤링 인프라 + 이용약관 위반 리스크가 따라옵니다.

> **대안**: 네이버 쇼핑 API / 쿠팡 파트너스 등 공식 제휴 API로 축소.
> "최저가 엔진"이 아니라 **"목표가 도달 알림"** 으로 좁히면 현실적이고, 제휴 수수료라는 수익모델도 자연스럽게 붙습니다.

## 4. 검증 안 된 핵심 가정

| # | 가정 | 위험도 | 가장 싼 검증법 |
|---|---|---|---|
| 1 | 사람들이 선물/경조사를 **기록할 만큼** 귀찮음을 감수한다 | 🔴 최상 | 지인 20명 인터뷰 — "지금 경조사 어떻게 관리하세요?" 엑셀·메모앱 사용자가 몇 명인지 집계 |
| 2 | 상호성 데이터를 **숫자로 보는 것이 불쾌하지 않다** | 🟠 높음 | 목업 A/B — "김철수 −5만원" vs "김철수님께 답례할 차례예요" 반응 비교 |
| 3 | 위시리스트/펀딩에 **상대방도 가입한다** | 🟠 높음 | 초대 없이 혼자 써도 가치가 있는지 확인 |

**가정 3이 특히 중요합니다.**
장부는 혼자 써도 가치가 있지만(single-player), 펀딩·위시·교환은 **상대방도 앱을 설치해야** 합니다(multi-player).
팀 프로젝트에서 multi-player 기능부터 만들면 시연 시 **텅 빈 화면**을 보게 됩니다.

## 5. 권장 MVP

> **"혼자 써도 가치 있는 경조사·선물 장부"** + 자동 입력 + 금액 추천

### v1 (필수)

- ✅ 관계별 통합 장부 (경조사 + 선물)
- ✅ SMS / 청첩장 링크 자동 입력 — *마찰 제거, 제품의 생사*
- ✅ 상호성 밸런스 + 금액 추천 (물가 보정) — *유일한 해자*
- ✅ 다가오는 경조사 알림

### v2 (다음)

- 🔸 위시리스트 + NO리스트 + 중복 경고
- 🔸 공동 펀딩 (§2-D 실패 경로 설계 완료 후)
- 🔸 목표가 알림 (제휴 API 기반)

### 보류

- ⛔ 선물 교환 + 포인트 환급
- ⛔ 자체 최저가 크롤링

### Anti-goal (명시적으로 만들지 않는 것)

커머스 · 결제 정산 · 소셜 피드
