## 0. 축 이동 — v2에서 무엇이 틀렸나

| | v2 (내가 잡았던 축) | v3 (확정) |
|---|---|---|
| **문제 정의** | 커뮤니케이션 문제 — "말하기 민망하다" | **정보 문제 — "나를 충분히 모른다"** |
| **핵심 자산** | NO리스트 (부정 선호) | **취향 프로필 (기호 + 맥락 + 이야기)** |
| **NO리스트의 위치** | 메인 기능 | 취향 프로필의 **한 필드** |
| **감정 톤** | 회피 — "싫은 걸 피하자" | **애정 — "나를 아는 선물"** |

> **피드백 수용**: "받기 싫은 선물"이라는 부정 프레이밍과 민망함 축은 과했습니다.
> 민망함은 **부산물**이지 원인이 아닙니다. 진짜 원인은 **선물하는 사람이 쓸 수 있는 정보가 너무 얕다**는 것입니다.

### ⚠️ 이름과 축의 관계

`넌지시`는 **방식**(어떻게 전달하나)을 가리키고, 축은 **결과**(얼마나 나에게 맞나)로 이동했습니다. 충돌은 아니지만 이름만으론 가치가 안 잡히므로 **태그라인이 결과를 보완**해야 합니다.

```
넌지시
나를 아는 선물.

또는

넌지시
취향은 넌지시, 선물은 정확하게.
```

## 1. 주제 디벨롭 — "기호를 넘어선 취향과 이야기"

### 취향에는 3개의 층이 있습니다

이 서비스가 기존 위시리스트와 갈리는 지점이 여기입니다.

| 층 | 예시 | 이 층만 알면 나오는 선물 |
|---|---|---|
| **1. 기호** | "커피 좋아함" | 아무 커피 기프티콘 |
| **2. 취향** | "산미 있는 원두, 핸드드립, 아침에만" | 드리퍼, 원두 |
| **3. 이야기** | "출근 전 15분 혼자 내리는 게 유일한 나만의 시간" | **온도계 달린 케틀, 원두 정기구독, 타이머** |

**3층에 도달해야 선물이 달라집니다.** 그리고 3층은 지금 어떤 서비스도 담지 않습니다 — 여기가 넌지시의 자리입니다.

> **입력 UI 제안**: "왜 좋아하세요?" 한 줄 자유 입력. 필수 아님. 쓰면 쓸수록 선물이 좋아진다는 걸 보여주면 채워집니다.

### 대분류 vs 상세 옵션 — 설계는 맞습니다. 단 **용도가 다릅니다**

> *"'텀블러'같이 큰 분류로 선택하고, '스타벅스 텀블러' 같은 상세는 유저의 선택에 맡김"*

입력 부담 측면에서 **옳은 판단**입니다. 상세까지 강제하면 온보딩에서 다 이탈합니다. 다만 이 둘은 **다른 데이터**이고 **다른 곳에 쓰입니다.**

| | 대분류 | 상세 + 이야기 |
|---|---|---|
| 입력 비용 | 태그 탭탭탭 — **30초** | 자유 입력 — 몇 분 |
| 강제성 | 온보딩 필수 | **선택** |
| 용도 | **제외 필터** — "텀블러는 빼고 보여줘" | **추천 연료** — "이런 텀블러라면 좋아할 듯" |
| 없으면? | 잘못된 선물 방지 실패 | 평범한 선물이 나옴 |

> ⚠️ **주의**: 대분류만으로는 §0의 "개인 맞춤" 축을 달성할 수 없습니다. 대분류는 *실패를 막고*, 상세·이야기가 *성공을 만듭니다.* 대분류만 구현하면 v2의 NO리스트 서비스로 되돌아갑니다.

### 점진적 프로필링 (Progressive Profiling)

가입 시점에 전부 받으려 하지 마세요. 이탈합니다.

```
가입 (30초)     →  대분류 제외 태그 5개, 알러지/사이즈
                       ↓ 쓰면서 채워짐
선물 받은 후    →  "이 선물 어땠어요?" → 취향 데이터로 환류
친구 생일 D-7   →  "○○님이 당신 취향을 봤어요. 한 줄 더 적어볼까요?"
```

**받은 선물의 후기가 가장 값싼 취향 데이터입니다.** 사용자가 자기소개서를 쓰는 게 아니라, 실제 사건에 반응하게 만드세요.

## 2. 펀딩 — 반박 수용

> *"싫어하는 선물은 1:1, 펀딩은 1:n. 그리고 고가이므로 민망함과 상충한다고 하기에는 어렵다. 오히려 상대방에게 금액과 고민을 덜어주기 위한 추천안 느낌."*

### ✅ 대체로 타당합니다

1. **축이 바뀌면서 제 지적의 전제가 사라졌습니다.** "민망함"이 더 이상 중심축이 아니므로, 펀딩과의 충돌도 함께 약해집니다.
2. **1:1 vs 1:n 구분은 유효합니다.** 1:1에서 "이거 사줘"는 부담이지만, 1:n에서는 **"이건 혼자 사줄 수 없는 것"이 자명**해서 요구로 읽히지 않습니다. 5만원짜리를 올리면 "누가 사줘"지만, 100만원짜리는 "이런 게 갖고 싶다"는 표현에 가깝습니다.
3. **"금액과 고민을 덜어준다"는 프레이밍이 제 것보다 낫습니다.** 주는 사람의 효용을 정면으로 말합니다.

### 더 강한 프레이밍 제안

v3 축에 맞춰 펀딩을 이렇게 정의하면 **축과 완전히 일관**됩니다.

> **펀딩 = 개인 맞춤 선물의 가격 상한을 올리는 장치**

취향을 아무리 잘 알아도 예산이 3만원이면 "그 사람에게 딱 맞는 100만원짜리"는 줄 수 없습니다. 펀딩은 **맞춤의 천장을 뚫는 수단**입니다. 별도 기능이 아니라 같은 축의 연장선입니다.

### 다만 남는 것 — 심리가 아니라 **운영**

| 항목 | 상태 |
|---|---|
| 미달 시 차액 부담자가 **주최자인지 받는 사람인지** | ❌ 미결 (v2 §4에서 이월) |
| 펀딩 **개설 주체** — 받는 사람 / 주최자 | ❌ 미결 |
| 최소 인원 없음 → **사실상 매번 미달** 발생 | ❌ 미결 |
| 지분 표시 범위 | ❌ 미결 |

> 심리적 모순 지적은 철회하지만, **위 4개는 여전히 정해야 굴러갑니다.**

## 3. 선물 교환 — 설계가 개선됐습니다

### ✅ 흐름 설계 자체가 v2 대비 크게 나아졌습니다

```
흐름1:  A 선택 → B 승인 → 결제
흐름2:  A 선택 → B 반려 → 결제요청 취소 → B가 이하 가격 선택 → 결제
```

**결제를 B의 승인 뒤로 미룬 것이 핵심입니다.** 이 한 가지로 v2에서 제기했던 두 문제가 구조적으로 사라집니다.

| v2에서 지적한 문제 | v3 흐름에서 |
|---|---|
| A의 결제금이 특정 상품에 묶이지 않고 떠돎 → 사실상 상품권 | ✅ **소멸** — 결제가 확정 후 1회만 발생 |
| 차액 5,000p → 선불전자지급수단 규제 | ✅ **소멸** — 차액이 애초에 결제되지 않음 |

### 동의 문구 아이디어 — 방향은 맞습니다

> *"'주는 선물 가격 이하의 선물로 재결제될 수 있다'라는 동의 요구 문구를 띄우면 안 되나?"*

**됩니다.** 그리고 그게 정석에 가깝습니다. 결제자는 여전히 **A**이고, B는 상품을 고르는 사람일 뿐입니다. A는 "상한 3만원 범위 내에서 B가 선택한 상품"에 대해 결제를 동의한 것이 됩니다.

동의가 유효하려면 최소한 이 조건을 갖춰야 합니다:

- **금액 상한이 명시적으로 고정**될 것 — A가 지정한 금액
- **동의가 구체적**일 것 — 약관 매몰 ❌, 결제 직전 별도 화면 ✅
- **A가 확정 전까지 철회 가능**할 것
- **결제 결과가 A에게 고지**될 것 (아래 참조)

> ⚠️ 실제 적용은 **전자상거래법·여신전문금융업법 검토가 필요한 사항**입니다. 다만 구조 자체는 막히지 않습니다.

### 🔴 남은 문제 4개 — 동의 문구로 해결되지 않는 것

**① A에게 반려 사실을 알리는가?**

이게 최대 미결 쟁점입니다.

| | 알린다 | 알리지 않는다 |
|---|---|---|
| 법적 | ✅ 깔끔. 청약철회권 행사 가능 | 🔴 A가 뭘 샀는지 모른 채 결제됨 |
| 감정 | 🟡 A가 무안함 | 🟡 나중에 "그 마우스 잘 써?" 문제 |
| 결제 고지 | 정상 | **결제 문자에 가맹점·금액이 찍히므로 어차피 드러남** |

> **결제 고지는 숨길 수 없습니다.** 카드 승인 내역과 영수증에 기록이 남습니다. "A는 모르도록"은 기술적으로 유지하기 어렵습니다. → **알리는 쪽으로 가되, 프레이밍을 부드럽게** 하는 것이 현실적입니다.

**② "반려"라는 단어의 감정 비용**

법적 문제보다 이것이 더 큰 제품 리스크입니다. A가 성의껏 고른 것을 B가 "반려"하면 관계에 흠집이 납니다.

> **제안**: "반려" 대신 **"다른 것도 좋아요"** / **"이것도 궁금해요"** 로 프레이밍. 거절이 아니라 **대안 제시**로 읽히게 하세요. 화면 문구 하나가 관계를 살립니다.

**③ 결제수단 유효기간**

A가 승인 요청을 보내고 B가 3일 뒤 확정하면, 그 사이 카드 한도·유효기간 문제가 생깁니다. **승인 요청 만료 기한**(예: 72시간)과 결제 실패 시 재요청 플로우가 필요합니다.

**④ 차액 처리**

A가 3만원을 걸었는데 B가 1만원짜리를 고르면? → **차액은 청구하지 않음**이 가장 깔끔합니다. 포인트·환급 없음. 다만 B는 "싸게 고르면 미안해서" 결국 상한 가까이 고르게 되므로, 실질 효과가 크지 않을 수 있음을 감안하세요.

## 4. 콜드 스타트 — 합의됨

> *"취향 입력은 가입 필수. 취향을 상대방에게 알리는 건 링크만으로 확인 가능하도록."*

✅ **동의합니다.** 진입 장벽이 한쪽(받는 사람)에만 생기고, 링크가 카톡으로 퍼지는 것 자체가 유통 채널이 됩니다.

### 추가로 설계해야 할 것 2가지

**① 링크 → 가입 전환 지점**

링크 열람자가 **"선물하기"를 누르는 순간**이 유일한 가입 요구 지점입니다. 여기가 이 서비스의 실질적 퍼널 병목입니다. 열람 단계에서는 가입을 절대 요구하지 마세요.

**② 🔴 링크 프라이버시**

취향 데이터는 생각보다 민감합니다.

```
알러지                 → 건강 정보
사이즈                 → 신체 정보
선호 브랜드·가격대     → 소득 추정 가능
"나만의 시간" 같은 이야기 → 사생활
```

**링크를 아는 사람은 누구나 볼 수 있다**는 건 위험합니다. 최소한 다음 중 하나는 필요합니다:

- 링크 **만료 기한** (예: 30일)
- **공개 범위 분리** — 기본 정보는 링크 공개, 상세·이야기는 친구 승인 후
- 조회 로그 — "누가 내 취향을 봤는지"

> 조회 로그는 프라이버시 장치이면서 동시에 **"○○님이 당신 취향을 봤어요" 알림 = 리텐션 훅**이 됩니다.

## 5. UI 초안 리뷰

> 반응형(모바일 기준) · 하단 4탭: **홈**(선물 검색, 카테고리) / **친구 목록** / **캘린더** / **마이**(프로필 설정, 싫은 선물, 펀딩 내역)

### ✅ 잘한 것

- **4탭** — 3~5탭 표준 안에 있습니다. 적절합니다.
- **모바일 우선** — 선물은 이동 중·카톡 알림에서 시작되는 행동이라 맞습니다.

### 🔴 문제 4가지

**① 홈 = 선물 검색이면 일반 쇼핑앱과 구분되지 않습니다**

이 서비스의 첫 화면이 검색창이면, 사용자는 쿠팡을 켰을 때와 같은 화면을 봅니다. **넌지시의 차별점(관계 + 취향)이 첫 화면에서 사라집니다.**

> **홈은 관계 중심 액션 허브여야 합니다.**
> - 다가오는 친구 일정 + 그 친구의 취향 요약 카드
> - **승인 대기 중인 선물** (아래 ② 참조)
> - 진행 중인 펀딩

**② 승인/반려 진입점이 네비에 없습니다**

§3의 흐름이 이 UI에 반영되어 있지 않습니다. **시간 민감한 액션**(만료 72시간)인데 어느 탭에서 처리하는지 정의되지 않았습니다. → 홈 최상단 + 푸시 알림이 맞습니다.

**③ "마이 > 싫은 선물"은 v3 축과 충돌합니다**

부정 프레이밍이 UI에 남아 있습니다. §0에서 축을 옮긴 만큼 여기도 바뀌어야 합니다.

```
❌ 마이 > 싫은 선물

✅ 마이 > 내 취향
            ├─ 좋아하는 것
            ├─ 이야기
            ├─ 이미 있어요        ← 구 "싫은 선물"
            └─ 못 써요 (알러지·사이즈)
```

**④ 캘린더 탭의 사용 빈도**

생일은 1인당 1년에 1회입니다. 캘린더를 독립 탭으로 두면 **4탭 중 하나가 거의 안 열립니다.** 친구 탭에 흡수하고, 그 자리를 검색에 주는 게 효율적입니다.

### 수정 제안 (4탭 유지)

| 탭 | 내용 | 변경 |
|---|---|---|
| **홈** | 다가오는 일정 · **승인 대기** · 진행 중 펀딩 | 🔄 검색 → 액션 허브 |
| **친구** | 친구 목록 + 취향 카드 + **캘린더 흡수** | ➕ 캘린더 통합 |
| **선물** | 검색 · 카테고리 (기존 홈 기능) | 🔄 캘린더 자리로 이동 |
| **마이** | **내 취향** · 선물 내역 · 펀딩 내역 · 설정 | 🔄 "싫은 선물" → "내 취향" |
