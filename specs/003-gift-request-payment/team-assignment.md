M2의 "**스토리로 자른다**"를 유지하되, M3에는 **전문 축 두 개가 층으로 남는다** (초안 §2).

   5종 + CHECK 4종이 한 번에 들어가 어느 때보다 무겁다.

   처리의 일관성이 한 사람 손에 있어야 한다.

## 3. 공통 — 전원이 각자 하는 것

### T001 — `.env.local`에 M3 env 추가

```bash
PORTONE_MODE=mock
BILLING_KEY_ENCRYPTION_KEY=   # openssl rand -base64 32
GIFT_RESPOND_TTL=5m
GIFT_PAYMENT_RETRY_WINDOW=24h
GIFT_PAYMENT_MAX_ATTEMPTS=3
```

> 🔒 `.env.local`은 절대 커밋하지 않는다. **PortOne 실키가 생기는 순간부터 특히.**
> E2E 계정은 M2의 2개(`E2E_USER_*`·`E2E_USER2_*`)를 그대로 쓴다 — **3계정은 M4부터.**

### M1·M2에서 이어지는 함정 셋

- **`skipped` 수를 확인한다** — env가 비면 E2E가 실패 대신 조용히 skip 된다
- **개발 서버는 `:3000` 고정** — 두 개 띄우면 Playwright가 안 돈다. HTTP 431이면 `localhost` 쿠키 삭제
- **`db push` 금지** — raw SQL CHECK 4종이 안 들어간다. 새 환경은 `migrate dev`/`deploy`로

## 6. 협업 규칙 — M3에서 새로 생기는 것만

M1·M2 규칙(DAL 경유·테스트 먼저·마이그레이션 J만·`.env.local` 커밋 금지·`:3000`·`skipped`
확인·착수 전 한 줄 공유·브랜치 push)은 전부 유지. 추가는 다섯이다.

| 규칙 | 이유 |
|---|---|
| **`PORTONE_MODE=mock`이 기본, E2E는 항상 mock** | 실키로 E2E를 돌리면 테스트가 실결제를 만든다 |
| **동의 문구를 고치면 반드시 `CONSENT_VERSION`을 올린다** | 결제 권한 위임의 증빙 — 리뷰 체크 항목 |
| **TTL·재시도 값은 전부 env** (T009 헬퍼 경유) | PRD: "설정 가능해야 하며 실서비스 배포 시 조정" |
| **카운트다운은 T020 하나만 쓴다** | 화면마다 만들면 만료 표시가 어긋난다 |
| **상태를 직접 UPDATE 하지 않는다 — T015 전이 함수 경유** | 전이가 흩어지면 조합 버그가 파일 경계에서 샌다 |
