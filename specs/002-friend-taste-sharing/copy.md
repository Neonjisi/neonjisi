# M2 문구 보완 — 확정안

**소유**: S(기획) · **대상**: `specs/002-friend-taste-sharing` 친구·링크 화면
**연결**: FR-017(성사 알림) · FR-013(즉시 성사) · M4 `copy.md` §1(어체 규칙)

이 문서가 M2 문구의 원본(SSOT)이다. 코드에 있는 문장을 고칠 때는 **여기를 먼저 고치고**
코드를 맞춘다. 반대 방향은 안 된다.

M4 와 성격이 다르다. M4 `copy.md` 는 화면 전체를 백지에 가깝게 확정한 문서지만, 이것은
**어체 규칙을 M2 화면에 적용한 보완 패스**다. 규칙 자체는 M4 문서가 원본이고 여기서
다시 정의하지 않는다.

> **기준**: 2026-09-07 문구 보완 커밋. 아래 line 번호는 그 커밋 기준이다.

---

## 1. 적용한 규칙

M4 `copy.md` §1 을 그대로 쓴다. 요약만 옮긴다.

| 구분 | 어체 | 판정 |
|---|---|---|
| 사전 고지 · 동의 | **-습니다** | 그 일이 **일어나기 전**에 보인다 |
| 사후 안내 · 상태 · 알림 | **-어요** | 그 일이 **일어난 뒤**에 보인다 |

1인칭은 **"내"** 다. M2 화면에는 `제`·`저` 위반이 없다 (확인 완료).

---

## 2. 고친 곳 — 3건 (①② 2026-09-07 문구 보완 · ③ 같은 날 뒤집음 → §3)

### ① 성사 알림 (FR-017)

`lib/notification/display.ts:52`

```
- {N}님이 링크로 친구가 되었습니다
+ {N}님이 링크로 친구가 되었어요
```

**이유**: 알림은 사후다. 그리고 **알림 12종 중 이 줄과 M3 `:65` 둘만 `-습니다`였다.**
알림 목록은 M2·M3·M4 알림이 한 화면에 섞여 렌더되므로, 두 줄만 격식체면 사용자가
한 목록에서 두 어체를 본다. M4 `copy.md` §1 이 이 사실을 적어두고 "M2·M3 문구 보완에서
맞춘다"고 미뤄둔 것을 여기서 해소한다.

### ② 즉시 성사 결과 화면 (FR-013)

`app/i/[token]/page.tsx:36`

```
- {N}님과 친구가 되었습니다
+ {N}님과 친구가 되었어요
```

**이유**: 링크를 연 순간 이미 친구가 됐고(FR-013), 이 화면은 그 **결과**다. 사후다.

> 이 화면은 첫 훑기에서 빠졌다 — 대상 디렉터리를 `app/friends`·`components/friend` 로만
> 잡아서 `app/i/` 가 들어가지 않았다. M2 화면을 다룰 때 **초대 수락 경로(`app/i/`)를
> 빼먹지 말 것.**

## 3. 그대로 둔 곳 — 6건

전부 **사전 고지**라 `-습니다` 가 맞다. 바꾸면 규칙 위반이 된다.

| 위치 | 문구 | 왜 사전인가 |
|---|---|---|
| `components/friend/remove-friend-dialog.tsx:164` | 서로의 취향을 볼 수 없게 됩니다 | 해제를 **누르기 전** 확인 다이얼로그 |
| `components/friend/remove-friend-dialog.tsx:166` | 진행 중인 선물은 그대로 진행됩니다 | 〃 |
| `components/friend/revoke-link-dialog.tsx:137` | 이 링크로는 더 이상 친구가 될 수 없습니다 | 중지를 **누르기 전** 확인 |
| `components/friend/revoke-link-dialog.tsx:138` | 이미 친구가 된 사이는 그대로 유지됩니다 | 〃 |
| `components/friend/revoke-link-dialog.tsx:139` | 새 링크는 언제든 다시 발급할 수 있습니다 | 〃 |
| `app/friends/invite/page.tsx:16` | 링크를 보내면 받은 사람이 바로 친구가 됩니다. | 링크를 **보내기 전** 즉시 성사 고지 (FR-014) |

### 한 번 뒤집은 것 — `components/friend/friend-list.tsx:12`

```
- 링크 하나면 시작됩니다
+ 링크 하나면 시작돼요
```

친구 0명일 때의 빈 상태 헤딩이다. **처음에는 "카피 성격이 강해 그대로 둔다" 고 판단했다.**
온보딩 히어로와 같은 결로 보였기 때문이다. M1 보완(2026-09-07)에서 블록 전체를 다시
보고 뒤집었다.

```
<h2>링크 하나면 시작돼요</h2>
<p>친구에게 링크를 보내 서로의 취향을 나눠보세요.</p>   ← 이미 친근체였다
<LinkButton>친구에게 링크 보내기</LinkButton>
```

**바로 아래 줄이 이미 `-세요` 다.** 세 줄 블록에서 헤딩만 격식체였다. 온보딩 인트로는
부제까지 격식이라 블록이 한 톤이지만 여기는 아니었다.

판정 기준: **블록 안에서 이미 어체가 갈려 있으면 바꾼다. 블록 전체가 한 톤이면 톤으로 본다.**
M1 `copy.md` §3 에 두 자리의 비교표가 있다.

## 4. 검증

문구를 바꾸면 그 문구를 고정한 테스트도 같은 크기의 작업이다 (M4 T044 에서 배운 것).

| | |
|---|---|
| 고친 테스트 | `notification-display.test.ts:68` · `notification-list.test.tsx:41·67` |
| 단위·통합 | 600 통과 |
| E2E | `friend-invite` 8/8 (chromium) |

`app/i/` 변경은 E2E 가 `/친구가 되었\|친구가 됐/` 로 느슨하게 잡고 있어 스펙 수정이
필요 없었다 (`friend-invite.spec.ts:47` · `invite-control.spec.ts:45` ·
`funding-settle.spec.ts:110`). **그 관용 정규식이 이번에 값을 했다.**
