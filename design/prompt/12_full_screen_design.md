# 12 — 넌지시 전체 기능 화면 설계 / 확장

> 실행 시점: `01~11` 완료 후
>
> 목적: 확정된 V2 디자인 시스템을 Single Source of Truth로 사용하여 PRD의 MVP 기능 화면 전체를 설계한다.

## 0. 확정 디자인 기준

다음 항목은 이미 확정되었으며 다시 탐색하지 않는다.

- Visual Direction: **V2 / Playful Minimalism**
- Color Direction: **Rose + Soft Apricot**
- Soft Apricot: **`#FBE2C1`**
- Font Family: **`Pretendard Variable`**
- Neo-Brutalism Accent: **Primary CTA / Button에만 제한**
- Foundation / Component / Token: STEP 01~11에서 확정된 디자인 시스템 사용

새로운 화면을 만들기 위해 임의 HEX, Font, Spacing, Radius, Shadow, Component Style을 직접 생성하지 않는다.
필요한 패턴이 기존 디자인 시스템에 없을 경우 먼저 기존 Component의 Variant로 해결 가능한지 검토하고, 불가능한 경우에만 최소한의 신규 Component/Variant를 추가한다.

---

# 1. 설계 근거

화면과 플로우의 기능적 근거는 `neonjisi.prd-v2.md`를 우선한다.

MVP 핵심 루프:

**맞춤 취향 기록 → 친구에게 전달 → 취향 기반 선물 선택 → 수령자 승인/대안 제시 → 결제**

고가 선물에는 공동 펀딩 플로우가 추가된다.

디자인 과정에서 PRD에 없는 정책이나 기능을 임의로 확정하지 않는다.
Open Question에 해당하는 기능은 별도 표시하고 핵심 MVP Flow와 분리한다.

# 2. 전체 화면 구조

## A. Entry / Account

### A01. 시작 / 로그인
목적:
- 서비스 진입

### A02. 회원가입
목적:
- 친구 추가 링크를 통한 신규 사용자 포함

### A03. 친구 초대 링크 미리보기
목적:

- 가입 동기 제공

### A04. 친구 요청 수락
목적:
- 링크 발신자 확인
- 친구 관계 생성

# 5. Responsive 기준

PRD 요구사항에 따라 모바일을 기준으로 설계하되 반응형을 고려한다.

1차 작업:
- Mobile 기준 화면 완성

2차 검증:
- Tablet에서 정보 밀도와 Grid 확장 검토
- Desktop에서 과도하게 늘어나는 Width 제한
- 핵심 Flow와 Component hierarchy 유지

모바일 / 태블릿 / 데스크톱마다 별개의 디자인 언어를 만들지 않는다.

---

# 6. 화면 생성 공통 규칙

- STEP 01~11에서 만든 Foundation과 Component를 먼저 확인한다.
- 기존 Component가 있으면 반드시 Instance/Variant를 재사용한다.
- 임의 HEX 사용 금지. Soft Apricot은 `#FBE2C1`.
- Font는 `Pretendard Variable`.
- 새로운 spacing 값을 임의로 추가하지 않는다.
- Primary CTA/Button 외에 Neo-Brutalism hard offset shadow를 확장하지 않는다.
- 사람 → 취향 → 선물의 우선순위를 유지한다.
- 상품 Grid가 관계/취향 맥락을 압도하지 않도록 한다.
- 승인/대안 제시는 수락/거절의 공격적인 이분법으로 표현하지 않는다.
- 새로운 정책을 UI 디자인 과정에서 임의로 결정하지 않는다.
- 화면마다 별도의 스타일을 만들지 않고 동일 Design System을 유지한다.

---

# 7. Out of Scope

MVP 화면에 포함하지 않는다.

- 포인트 / 자체 화폐
- 최저가 비교 / 가격 추적
- 자체 커머스 / 물류
- 소셜 피드
- 가입 없는 상세 취향 열람
- 경조사
- 가계부

경조사와 가계부는 Future 기능이며 현재 전체 화면 설계에는 포함하지 않는다.

---

# 8. Open Question 처리

다음은 디자인 과정에서 임의 확정하지 않는다.

- 타인의 취향 대신 등록
- 별도 월간 캘린더
- 수령자가 펀딩을 개설했을 때 차액 부담자
- 친구별 취향 공개 범위
- 친구 관계 해제 후 취향 정보 처리

필요한 경우 `OPEN QUESTION` Annotation을 추가하여 팀 결정이 필요함을 표시한다.
