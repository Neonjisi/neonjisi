# PEN 화면 동기화 기준

기준 브랜치: `jisang/pen-screen-sync`  
앱 기준: 현재 `main`의 `app/**/page.tsx` 및 화면 컴포넌트  
대상 파일: `design/neonjisi.pen`

## 동기화 원칙

- 화면 배경과 Top Bar 배경은 앱의 `background-default`로 통일한다.
- 최신 PEN의 공통 헤더는 아이콘 로고와 알림 버튼을 사용하고, 비로그인 랜딩·로그인은 큰 한글 로고를 사용한다.
- PEN의 기존 디자인 시스템 컴포넌트와 토큰을 우선 재사용한다.
- 동적 ID 라우트는 대표 데이터 상태 한 장과 사용자 판단이 달라지는 결과 상태를 각각 둔다.
- 실제 앱에서 추가된 화면은 `CURRENT · M{n}` 접두어로 별도 행에 배치한다.

## 현재 구현 화면 보드

- `IMPLEMENTED · 현재 구현 화면 보드 · 2026-09-08`은 `pt-shots`의 프로덕션 캡처 31장을 PEN에 배치한 기준 보드다.
- 기존 편집 가능한 UI 프레임과 팀 검토 노트는 수정하거나 삭제하지 않는다.
- 구현 화면과 디자인 프레임을 나란히 보며 차이를 합의한 뒤, 편집 가능한 프레임과 앱 코드를 함께 수정한다.
- 보드는 `scripts/sync-pen-implementation-board.mjs`로 재생성할 수 있다.

## 상품 선택 이후 선물하기 흐름

- `CURRENT · 상품 선택 이후 선물하기 흐름` 보드는 `/products`부터 `/my/gifts?tab=received`까지 15개 편집 가능 화면을 실제 이동 순서로 묶는다.
- 보내는 사람 흐름 1~7, 받는 사람 응답 흐름 8~12, 상세·보낸 내역·받은 내역 13~15 순서다. 마지막 두 화면에서 변경 전·후 상품이 양쪽 내역에 모두 표시되는지 비교할 수 있다.
- `/products?for=[userId] · 친구 필터 · 원하는 선물 표시`는 친구 필터 적용 뒤 별도 맞춤 추천 이동 없이, 친구가 적어둔 WANT 항목과 제외 안내를 상품 목록 안에서 바로 보여주는 화면이다.
- 기존 시안 프레임은 비교를 위해 유지하고, 흐름 보드는 `scripts/sync-pen-gift-flow.mjs`로 재생성한다.

### 알림 진입 동선

- 홈 헤더의 종 아이콘 및 미읽음 배지 → `/notifications?from=home` → 뒤로가기 `/`
- 마이 화면 헤더의 종 아이콘 → `/notifications?returnTo=%2Fmy` → 뒤로가기 `/my`
- PEN 홈의 `TRtfN > CegZ5 > ajjmQ`가 실제 홈 알림 버튼의 시각 기준이다.

### 설정 진입 동선

- 마이 탭의 `약관 · 개인정보처리방침` → `/settings` → 뒤로가기 `/my`
- PEN의 `KvkwN`이 실제 설정 화면의 시각 기준이다.
- 설정 화면은 서비스 내 필수 알림 세 종류를 항상 받음으로 표시한다. 푸시 알림 저장 정책은 별도 구현 대상이다.

## 2026-09-08 PEN → 서비스 재동기화

- 인증 화면의 공통 헤더를 PEN `App/Header Standard` 기준의 80px 높이와 로고·뒤로가기·문맥 액션·알림 구조로 통일했다.
- 공통 헤더 알림은 현재 경로와 쿼리를 `returnTo`로 보존하며, 알림 화면의 뒤로가기는 진입 화면으로 복귀한다.
- 버튼 크기는 PEN 디자인 시스템의 `sm 32px` · `md 40px` · `lg 48px` 체계로 맞췄다.
- 랜딩·로그인·기본 프로필·온보딩, 홈·마이·일정, 선물 전송 완료 화면을 최신 PEN 구성에 맞췄다.
- 홈은 확인 대기 선물의 상품·가격·남은 시간과 CTA, 다가오는 일정의 D-day, 진행 중 펀딩을 PEN 순서로 표시한다.
- 마이는 `내 정보`·`선물 관리`·`설정`으로 메뉴를 묶고 중복 알림 메뉴를 제거했다. 알림은 공통 헤더에서 진입한다.
- 선물 내역 → 상세는 보낸/받은 탭으로, 상품 필터 → 상세 → 선물 확인은 원래 필터 쿼리로 돌아가도록 복귀 경로를 보존한다.
- `scripts/audit-pen-routes.mjs`가 실제 페이지, PEN 화면 이름, 고정 링크·뒤로가기·리다이렉트 대상을 양방향 검사한다.
- 목적지가 정의되지 않은 PEN의 장식용 말줄임표는 실서비스에서 무동작 버튼으로 만들지 않는다. 친구 삭제·주최자 펀딩 관리처럼 실제 동작이 있는 화면에만 문맥 액션을 노출한다.

### 최종 전 화면 재검토

- PEN의 66개 화면·상태를 앱의 35개 페이지 라우트 및 조건부 상태와 다시 대조했다.
- 홈·마이뿐 아니라 초대 토큰의 미리보기/완료/만료/내 링크, 선물의 진행/변경/완료/실패/만료/취소, 펀딩의 개설/참여/성사/미달/차액/취소, 공통 404/오류 상태를 각각 확인했다.
- PEN에는 있었지만 앱에서 빠졌던 선물 결과·펀딩 결과·초대 토큰·404·오류 화면의 공통 헤더와 하단 내비게이션을 반영했다.
- 만료된 초대 링크 CTA를 PEN과 같이 `링크 생성하기`로 바꾸고 `/friends/invite`에 연결했다.
- 고정 링크·뒤로가기·리다이렉트 45개는 모두 실제 앱 라우트로 연결된다.
- CTA 재검토에서 결제 동의의 최종 문구를 `선물하기`로 통일하고, 전송 완료는 PEN처럼 `홈으로` 하나만 남겼다.
- 펀딩 참여 완료에는 `펀딩 보기`와 실제 Web Share/링크 복사로 동작하는 `친구에게 알리기`를 연결했다.
- 상품 목록 → 상세 → 친구 선택 → 요청 확인 → 결제 동의 → 완료, 결제수단 강제 등록 후 복귀, 펀딩 개설 중 카드 등록 후 단계 복귀의 `returnTo` 보존을 다시 확인했다.
- 알림 11종은 친구 상세·선물 상세/결과/복구·펀딩 상세/결과 중 각 상태에 맞는 화면으로 이동한다.
- 최종 상태별 재검토에서 펀딩 성사·미달·차액 CTA는 `확인`→홈, 취소 상태만 `펀딩 내역 보기`→`/my/fundings`로 분리했다.
- 초대 수락 완료의 보조 CTA는 PEN처럼 `홈으로`→`/`로 맞췄다.
- 친구 상세는 `{친구 이름}에게 선물 고르기`, 받은 선물 응답은 `다른 선물이 더 좋아요`로 PEN 문구를 맞췄다.
- 상품 상세의 두 CTA는 문서 전체 이동을 일으키는 `<a>` 대신 Next 앱 내부 이동을 사용해 `for`·`returnTo` 흐름을 유지한다.
